# 08. План разработки и критерии приёмки

## Этап 0 — решение о продукте

Согласовать аудиторию, обещание и границы сервиса, юрисдикции, хранение данных, поставщиков и бюджет. Исследовать 10–15 целевых пользователей и проверить флагманский диалог, практику и игру. Число — ориентир для ранних качественных интервью, не статистическая оценка рынка.

## Этап 1 — технический фундамент

Репозиторий, дизайн-система, мобильный клиент/PWA, API, БД, аутентификация или осознанный гостевой режим, согласия, экспорт и удаление, CI/CD, события качества. Перенести экраны из прототипа без копирования его `localStorage` как серверной архитектуры.

## Этап 2 — первый настоящий сценарий

Один качественный разговор о сложной ситуации на работе, одна экспертно проверенная практика, дневник с местами, одна полноценная ветвящаяся история. Текст и диктовка; голосовой ответ — отдельный этап. Небольшой каталог практик с редакционным процессом.

## Этап 3 — места и пилот

Договорный источник мест, рейтинг с числом отзывов, фильтры доступности и дороги. Соцсигнал только после доказанного доступа и методики. Закрытый пилот, тесты вредных/бесполезных ответов, доступности и удаления данных. Расширять каталог и игры по результатам пилота.

## Приёмка разработки

- Разработчик может локально поднять приложение по README и выполнить миграции.
- Тестовый аккаунт видит данные на втором устройстве, а удаление действительно удаляет связанные записи по принятой политике.
- Диалог отвечает на конкретные детали 50 заранее размеченных сценариев и сохраняет границы безопасности.
- В календаре не появляются неподтверждённые GPS-посещения и игровые события.
- Любимые места выше новых; рейтинги и социальные показатели имеют источник и дату либо отсутствуют.
- При падении ИИ/карт приложение не показывает ложные факты и сохраняет доступ к личным записям.
- На небольшом экране основные сценарии работают одной рукой, с клавиатурой и экранным диктором.

## Команда для оценки работ

Продакт/UX, мобильная или веб-разработка, серверная разработка, QA, психологический эксперт, редактор практик, игровой сценарист/дизайнер, иллюстратор, специалист по защите данных. Стек и смету утвердить после решения об аудитории, географии и объёме пилота. Не оценивать полноценный продукт по времени создания статического прототипа.
