# 06. Места под настроение и места в дневнике

## Текущий пользовательский путь

В боковом и нижнем меню есть «Места». Пользователь выбирает одно из восьми настроений: грустно, тревожно, романтично, весело, спокойно, хочется нового, устало, хочется общения. Сначала показываются места, отмеченные сердечком, затем новые подходящие места около указанной точки. Точку можно получить только по нажатию геолокации или ввести город/район. Выбранный вручную город запоминается в браузере для следующего просмотра. Поиск города означает поиск около центра найденного района, а не «около пользователя». Ссылка ведёт на карту. «Была/был здесь» записывает место в сегодняшний дневник; посещение никогда не выводится автоматически из геолокации.

Дневник показывает места по календарным датам. Запись можно создать за прошлый день, указать примерное время, район, тип, впечатление и заметку, исправить или удалить. Любимое место можно выбрать повторно. Игровые события в этот календарь не попадают.

## Правило ранжирования будущей версии

1. Отфильтровать по доступности данных, разумной удалённости и выбранным ограничениям (пешком/транспорт, бюджет, безбарьерность, открыто сейчас — только когда эти поля достоверны).
2. Отдельная секция подходящих любимых мест, расстояние по маршруту, если доступно. Ручное любимое без координат показывать с пометкой «расстояние неизвестно», не выдавать за близкое.
3. Остальные — соответствие настроению × расстояние/время пути × качество рейтинга (с числом отзывов) × личная обратная связь. Внутри секции дать переключение «Ближе», «Выше рейтинг», «Больше обсуждают» только если поля реально получены.
4. Популярность в соцсетях — отдельный сигнал с указанной платформой, периодом, методикой и правом использования. Количество проходов/посещений, просмотров видео и публикаций — разные метрики, не объединять их без определения.
5. Объяснение в карточке: почему предложено место и откуда рейтинг. Пользователь может скрыть место и изменить настроение.

## Источники

Прототип: OpenStreetMap/Photon для названия, категории и координат. Это публичный демонстрационный сервис, для масштаба нужен договорной/собственный провайдер с SLA и условиями хранения/атрибуции. Для рейтинга и количества отзывов возможен Google Places или другой лицензированный поставщик. Foursquare предоставляет некоторые сигналы рейтинга и посещаемости, но его foot traffic не является популярностью в соцсетях. Прямые агрегированные соцметрики нужно отдельно согласовать с платформами/партнёрами; ограниченный исследовательский API TikTok не следует закладывать как коммерческий источник.

Данные разных поставщиков не сливать по одному лишь названию: нужен `provider_place_id`, геопозиция, адрес, проверки дублей, правила атрибуции и лицензирования. Оплата и квоты API зависят от полей и объёма. Ключи хранятся на сервере, не в мобильном приложении.

## Приватность

Разрешение геолокации — только после явного действия, без фонового трекинга. Точный запрос не записывается в дневник; сохранённый вручную город можно удалить. Посещённое место — подтверждённая пользователем запись, не факт, выведенный по GPS. Записи мест могут раскрывать чувствительные привычки: шифрование на сервере, ограничение доступа, экспорт и удаление обязательны до реального запуска.

## Проверки

Сохранённый город → новое настроение без повторного ввода; отказ в геолокации → ручной ввод; фаворит без координат → честная метка; внешний сервис недоступен → любимые остаются; посещение → правильная дата в календаре; смена часового пояса; дубль места; удаление; права на изображения и отзывы.
